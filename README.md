# FragRank

Учебная клиентская часть портала рейтинга игроков Counter-Strike 2. Готовы главная страница, интерактивный рейтинг, профили и этап 4: сравнение двух игроков.

## Запуск

1. Откройте папку `FragRank` в Visual Studio Code.
2. Установите расширение **Live Server**, если оно ещё не установлено.
3. Нажмите правой кнопкой мыши на `index.html` и выберите **Open with Live Server**.
4. Проверьте переходы по меню. Для проверки мобильного вида уменьшите окно браузера до ширины менее 800 px или включите режим устройства в инструментах разработчика.

Установка npm-пакетов и сборка не нужны. Открывайте сайт через HTTP-сервер: ES-модули главной страницы, рейтинга, профиля и сравнения могут блокироваться браузером при запуске через `file://`.

## Данные и границы этапа

`js/players.js` — единственный источник данных для всех страниц: 30 реальных профессиональных игроков из шести команд. Никнеймы настоящие; команды зафиксированы по историческим составам Shanghai Major в декабре 2024 года и не заявлены как текущие. Справочные источники составов: [список участников и профилей](https://steamcommunity.com/sharedfiles/filedetails/?id=3373486755), [страница турнира](https://www.hltv.org/events/7524/perfect-world-shanghai-major-2024). Реальная статистика из этих источников не используется.

**Все числовые игровые показатели вымышлены.** Это указано на главной, в рейтинге и профиле. В исходных данных хранятся `id`, `nickname`, `country`, `team`, `matches`, `wins`, `kills`, `deaths`, `headshots`, `rounds`, `damage`. Один демонстрационный матч означает одну карту; у игроков одной команды совпадают матчи, победы и раунды. Этот набор не является журналом встреч, поэтому сумма матчей игроков не выдаётся за количество уникальных матчей.

`calculatePlayerMetrics()` из `js/metrics.js` вычисляет доступные у каждого игрока `kd`, `adr`, `hs` и `winRate` при создании набора:

- K/D = убийства / смерти.
- ADR = суммарный урон / раунды.
- HS% = убийства в голову / убийства × 100.
- Win Rate = победы / матчи × 100.

Главная показывает количество игроков, количество уникальных команд и средний FragScore. Сводка, лидер и топ-3 вычисляются из общего массива, без отдельных демонстрационных сумм или копий игроков. Старый `demo-data.js` оставлен как совместимый экспорт того же массива.

Профиль получает игрока по `player.html?id=...`. Он использует `players.js` и ту же функцию `rankPlayers()` из `metrics.js`, что главная, рейтинг и сравнение. Дополнительного набора данных, копий статистики и отдельной формулы рейтинга нет. Аналитика и страница информации о проекте пока остаются заготовками.

## FragScore и позиции

```text
FragScore = 0.35 × K + 0.30 × A + 0.25 × W + 0.10 × H
K = min(K/D / 2, 1) × 100
A = min(ADR / 120, 1) × 100
W = Win Rate, в процентах от 0 до 100
H = HS%, в процентах от 0 до 100
```

FragScore вычисляется функцией `calculateFragScore()` и находится в диапазоне 0–100. Доли K и A ограничены сверху; проценты также ограничены диапазоном 0–100. При нулевом знаменателе производный показатель равен 0; K/D при положительных убийствах без смертей равен Infinity, что даёт максимально допустимый вклад K. В текущем наборе все знаменатели положительны.

Все расчёты и сортировки используют неокруглённые значения. Округление применяется только для отображения: FragScore и K/D — два знака, ADR и проценты таблицы — один. Поэтому игроки с одинаковым отображаемым числом могут иметь разные позиции.

`rankPlayers()` возвращает новый массив, отсортированный по убыванию FragScore. При точном равенстве баллов порядок задаётся никнеймом, затем id. Позиции от 1 до 30 уникальны и сохраняются при поиске, фильтрах и сортировке по другим столбцам. Исходный массив не изменяется.

## Проверка рейтинга в браузере

1. Откройте `ranking.html` через Live Server. По умолчанию отображаются 30 игроков по убыванию FragScore; первый — donk с **73,75**.
2. Введите `nIkO`: должна остаться строка NiKo. Поиск не учитывает регистр, удаляет пробелы по краям и ищет подстроку никнейма. Очистите поле.
3. Выберите **Россия** и **Team Spirit**: останутся donk, sh1ro, magixx, chopper. Добавьте поиск `SH1` — останется sh1ro. Позиция берётся из общего рейтинга.
4. Введите несуществующий никнейм или выберите **Франция** и **MOUZ**: появится сообщение «Игроки не найдены». Нажмите «Сбросить всё» — вернутся все игроки, пустой поиск, все страны/команды и FragScore по убыванию.
5. Нажимайте **K/D**, **ADR**, **HS%**, **Win Rate**, **FragScore** или **#**. Первое нажатие нового столбца сортирует по убыванию, следующее — по возрастанию. Стрелка и `aria-sort` показывают активное направление.
6. Нажмите никнейм — адрес должен содержать `player.html?id=...`, а профиль должен показывать выбранного игрока и те же показатели.
7. На главной проверьте совпадение топ-3 с первыми строками рейтинга после сброса: donk, ZywOo, m0NESY. Сводка: **30** игроков, **6** команд, средний FragScore **61,30**.
8. Уменьшите ширину до 320–390 px: фильтры выстроятся вертикально, таблица будет прокручиваться внутри контейнера. Колонка игрока закреплена при горизонтальной прокрутке; область таблицы доступна с клавиатуры.

Для независимой проверки формулы выполните в консоли браузера на любой странице сайта:

```js
const { calculateFragScore } = await import('./js/metrics.js');
calculateFragScore({ kd: 1.2, adr: 84, winRate: 60, hs: 50 }); // 62
// 0.35 × 60 + 0.30 × 70 + 0.25 × 60 + 0.10 × 50 = 62
```

Для donk: K/D = 1050/700 = 1,5; ADR = 105600/1100 = 96; Win Rate = 35/50 × 100 = 70; HS = 630/1050 × 100 = 60. FragScore = 26,25 + 24 + 17,5 + 6 = **73,75**.

Автоматические проверки выполняются встроенным тестовым модулем Node.js, без npm-пакетов (Node нужен только для этих проверок, не для запуска сайта):

```text
node --test tests/metrics.test.mjs
```

## Профиль игрока и его проверка

`js/player.js` читает `id` через `URLSearchParams`. Идентификаторы совпадают с `id` из общего набора и учитывают регистр. Пробелы по краям удаляются. Пустой параметр, как и отсутствие `id`, открывает выбор игрока. Неизвестный идентификатор показывает отдельное сообщение со ссылками на рейтинг и выбор. Данные выводятся через `textContent`; содержимое URL не вставляется в HTML.

В профиле показаны никнейм, страна, историческая команда, глобальная позиция FragRank и FragScore. Семь карточек отображают Matches, Kills, Deaths, K/D, ADR, HS% и Win Rate. Формат чисел совпадает с рейтингом. Все данные относятся к одному общему демонстрационному набору, а не к отдельной статистике профиля.

Визуализация использует четыре горизонтальные полосы с независимыми шкалами: K/D — 0–2; ADR — 0–120 единиц урона за раунд; HS и Win Rate — 0–100%. Пороги 2 и 120 взяты как ориентиры нормализации FragScore, они не являются игровыми максимумами. Длина полосы ограничивается своей шкалой; фактическое число остаётся в подписи, в том числе при превышении ориентира. Для вспомогательных технологий полосы имеют роль `meter`, диапазон и текстовое описание значения. Matches, Kills и Deaths представлены абсолютными числами и не смешиваются с процентами на общей шкале.

Проверьте через Live Server:

1. Откройте `player.html?id=donk`. Ожидаются: **donk**, Россия, Team Spirit, **#01**, FragScore **73,75**; Matches **50**, Kills **1 050**, Deaths **700**, K/D **1,50**, ADR **96,0**, HS **60,0%**, Win Rate **70,0%**. Пробел в больших числах может быть неразрывным.
2. Полосы donk должны занимать: K/D **75%**, ADR **80%**, HS **60%**, Win Rate **70%** своих шкал. Подписи рядом показывают исходные величины, а не длину полосы в процентах.
3. Откройте `player.html?id=niko`: NiKo, Босния и Герцеговина, G2 Esports, **#04**, FragScore **70,38**. Сверьте с таблицей рейтинга. Поиск и фильтры рейтинга не меняют глобальную позицию профиля.
4. Откройте `player.html` и `player.html?id=`: показан поиск по общему набору из 30 участников. Введите `yWo`, выберите ZywOo из подсказок и нажмите «Открыть профиль» — должен открыться `player.html?id=zywoo` с позицией **#02**.
5. Откройте `player.html?id=unknown`: должно появиться сообщение «Игрок не найден» без пустых карточек и неверных показателей. Ссылка на рейтинг должна работать.
6. В рейтинге найдите `sh1ro` и нажмите его никнейм: откроется `player.html?id=sh1ro`, позиция **#05**, FragScore **66,20**.
7. В профиле нажмите существующую кнопку «Сравнить игрока»: откроется `compare.html?id=...` с тем же id. Этот игрок должен быть выбран именно слева, правое поле должно оставаться пустым.
8. Проверьте ширины **320**, **390**, **768**, **1280 px**: карточки перестраиваются, шкалы и подписи остаются читаемыми, горизонтальная прокрутка страницы не появляется. Проверьте форму выбора клавиатурой и мобильное меню.

Мобильное меню сохраняет прежнее поведение: кнопка «Меню», Escape с возвратом фокуса, переход по ссылке и клик вне шапки. Без JavaScript навигация остаётся видимой, а вместо интерактивного содержимого показаны пояснения.

### Поиск игрока с автоподсказками

Поле выбора на `player.html` реализовано как доступный combobox с `listbox`. `js/player-search.js` получает ссылку на общий массив из `player.js`; отдельного набора игроков нет. Поиск удаляет пробелы по краям, не учитывает регистр и находит любую часть никнейма. Пустое поле не открывает список. Подсказки содержат никнейм, команду и аватар с инициалами.

- Введите `NES`: появится m0NESY. Выберите подсказку — поле заполнится никнеймом, кнопка станет доступна, а скрытое поле `id` получит `monesy`.
- Введите `i`: проверьте несколько вариантов. Стрелки ↓/↑ перемещают выделение и прокручивают список; Enter подтверждает вариант (или первый, если выделения нет). После выбора повторный Enter или кнопка открывают профиль.
- Escape, Tab и клик вне поля закрывают список. Стрелки снова открывают его для текущего запроса.
- Введите `no-such-player`: под полем появится «Игроки не найдены»; открыть профиль нельзя.
- Выберите игрока и измените текст: сохранённый id очищается, кнопка блокируется. Даже если вернуть прежний никнейм вручную, нужно снова выбрать подсказку. Это исключает переход по устаревшему выбору.
- Проверьте мышь, клавиатуру и ширины 320–390 px. Список расположен поверх страницы, ограничен по высоте и прокручивается. Статистика, графики и прямые ссылки `player.html?id=...` работают как прежде.

## Сравнение игроков и его проверка

`compare.js` использует общий `players.js` и `rankPlayers()` для FragScore и глобальных позиций. `createPlayerAutocomplete()` из `player-search.js` создаёт независимые экземпляры поиска; `initPlayerSearch()` оставлен адаптером прежней формы профиля. Каждый экземпляр имеет собственное состояние и уникальные id подсказок. Списки кандидатов содержат ссылки на существующие записи игроков. Поиск, клавиатура, сброс при редактировании и закрытие списка одинаковы на обеих страницах.

Для FragScore, K/D, ADR, HS% и Win Rate отображаются зеркальные полосы относительно названия показателя. Обе стороны каждой строки используют одну шкалу: 0–100, 0–2, 0–120, 0–100% и 0–100% соответственно. Если данные превысят ориентир, шкала пары расширится до большего значения. Значения не суммируются между игроками и не нормализуются отдельно для каждой стороны. Большее значение выделяется оранжевым `#FF5A1F`; меньшее — серым. При точном равенстве оба нейтральны. Сравнение идёт до округления; формат подписей совпадает с рейтингом.

Matches, Kills и Deaths показаны отдельно, без определения победителя и цветового ранжирования. Количество Matches означает сыгранные карты, как и в общем наборе. Команды остаются историческим срезом декабря 2024 года, все числовые показатели — демонстрационные.

Проверьте через Live Server:

1. Откройте `compare.html`: оба поля пусты, показано приглашение выбрать двух игроков, кнопка обмена неактивна.
2. Откройте профиль `player.html?id=monesy` и нажмите «Сравнить игрока». На `compare.html?id=monesy` **левое поле содержит m0NESY, правое пусто**; видна только одна карточка участника и приглашение выбрать второго.
3. В правом поле введите `ONK`, выберите donk мышью или стрелками и Enter. Сравнение появится без перезагрузки. FragScore: **70,43 / 73,75**; K/D: **1,52 / 1,50**; ADR: **93,0 / 96,0**; HS: **40,0% / 60,0%**; Win Rate: **66,7% / 70,0%**. K/D выше у m0NESY, остальные четыре показателя — у donk.
4. Попробуйте выбрать m0NESY и справа: появится сообщение о повторном выборе, результаты для одинаковых игроков не показываются. Выберите другого участника.
5. Для donk и sh1ro Win Rate одинаковый (**70,0%**) — обе полосы этой строки серые и подписаны «Равно». У torzsi и broky равен K/D (**1,25**).
6. Нажмите «Поменять местами»: имена, поля, карточки, подписи и полосы должны обменяться сторонами. Цвет остаётся привязанным к большему показателю. Кнопка работает и с одним выбранным игроком.
7. Измените текст выбранного игрока: старый выбор сбрасывается, сравнение скрывается до подтверждения новой подсказки. Введите несуществующий никнейм — увидите «Игроки не найдены».
8. Нажмите «Сбросить сравнение»: оба поля, участники, результаты и сообщения очищаются, параметр `id` удаляется без перезагрузки.
9. Откройте `compare.html?id=unknown`: получите сообщение о неизвестном игроке и сможете выбрать пару вручную.
10. Проверьте 320, 390, 768 и 1280 px: поля перестраиваются на узком экране, полосы сохраняют общий центр и подписанные значения, страница не прокручивается по горизонтали. Поиск в профиле должен продолжать работать как раньше.

Параметр `id` всегда относится к **левому** участнику. При выборе, редактировании, обмене и сбросе он обновляется через `history.replaceState()` без перезагрузки. Второй участник не сохраняется в URL: при загрузке страницы правое поле остаётся пустым для нового выбора. Неизвестный id не подменяется случайным игроком.
