# FragRank

FragRank — учебный клиентский сайт рейтинга игроков Counter-Strike 2. Он позволяет изучать демонстрационные результаты, открывать профили, сравнивать участников и просматривать общую статистику.

**Все числовые игровые показатели вымышлены. FragScore — собственная учебная метрика. FragRank не связан с Valve и не является официальным ресурсом Counter-Strike 2.**

## Технологии

- HTML5: семантическая разметка, формы, таблица, шаблоны карточек.
- CSS3: Grid, Flexbox, media queries и диаграммы средствами CSS.
- Нативный JavaScript: ES-модули, DOM, URLSearchParams и History API.

Фреймворков, сторонних библиотек, backend, базы данных, сборки и внешних API нет. Для интерактивных функций нужен JavaScript. Все ресурсы сайта локальные; установка npm-пакетов не требуется.

## Локальный запуск

1. Откройте папку проекта в Visual Studio Code.
2. Установите расширение **Live Server**, если оно ещё не установлено.
3. Нажмите правой кнопкой на `index.html` и выберите **Open with Live Server**.
4. Пользуйтесь навигацией или откройте другую HTML-страницу на том же локальном сервере.

Запускайте сайт через HTTP-сервер: при открытии файла через `file://` браузер может блокировать ES-модули. Node.js не нужен для работы сайта; он используется только для автоматических проверок.

## Данные и показатели

`js/players.js` содержит 30 записей с реальными никнеймами и вымышленной игровой статистикой. Число стран и команд вычисляется из этих записей. Командные привязки — справочная информация набора, а не подтверждение актуальных составов или контрактов. Справочные источники исходных привязок: [список участников Shanghai Major 2024](https://steamcommunity.com/sharedfiles/filedetails/?id=3373486755), [страница турнира](https://www.hltv.org/events/7524/perfect-world-shanghai-major-2024). Реальные результаты из этих источников не используются.

В исходных данных хранятся `id`, `nickname`, `country`, `team`, `matches`, `wins`, `kills`, `deaths`, `headshots`, `rounds`, `damage`. Один демонстрационный матч означает одну карту.

Производные показатели вычисляются в `metrics.js`:

- **K/D** = убийства / смерти.
- **ADR** = суммарный урон / сыгранные раунды.
- **HS%** = убийства в голову / все убийства × 100.
- **Win Rate** = выигранные карты / сыгранные карты × 100.

Все страницы используют общий набор и общие функции. Сортировка и сравнение выполняются до округления; форматирование применяется только для отображения. Средние K/D, ADR и Win Rate на странице статистики — арифметические по игрокам с одинаковым весом каждого участника.

## FragScore

```text
FragScore = 0.35 × K + 0.30 × A + 0.25 × W + 0.10 × H
K = min(K/D / 2, 1) × 100
A = min(ADR / 120, 1) × 100
W = Win Rate в процентах от 0 до 100
H = HS% в процентах от 0 до 100
```

Вес K/D составляет 35%, ADR — 30%, Win Rate — 25%, HS% — 10%. Нормализованные K и A ограничены значением 100; итоговый FragScore находится в диапазоне 0–100. Веса выбраны для учебной задачи и не являются официальной методикой оценки игроков.

`rankPlayers()` создаёт производное представление данных с FragScore и глобальными позициями, сохраняя исходный массив. При равенстве баллов порядок определяется никнеймом, затем id. Позиции сохраняются при фильтрации и сортировке по другим столбцам.

## Поведение интерфейса

- Без `id` страница профиля показывает поиск. Например, `player.html?id=monesy` открывает m0NESY; идентификатор не обязан совпадать с написанием никнейма. Неизвестный id показывает сообщение и ссылку на рейтинг.
- Autocomplete ищет любую часть никнейма без учёта регистра. Поддерживаются ↑/↓, Enter, Escape, Tab и выбор мышью. Изменение текста сбрасывает выбранного игрока.
- В `compare.html?id=monesy` m0NESY выбран только **слева**, справа требуется второй участник. Одинаковые игроки не сравниваются. Состояние левого участника отражается в URL без перезагрузки; правый участник в URL не сохраняется.
- У каждой пары полос сравнения общая шкала. Большее значение выделено оранжевым; при равенстве оба серые. Matches, Kills и Deaths показаны без определения победителя.
- Страны по умолчанию показаны первыми восемью строками, команды — первыми шестью. Кнопка раскрытия появляется только при превышении соответствующего лимита. Раскрытие не пересчитывает данные, сохраняет проценты и шкалы; состояние команд сохраняется при сортировке.
- Все шесть команд текущего набора имеют по пять игроков. Поэтому смена направления сортировки не меняет их алфавитный порядок при равенстве.
- Диапазоны K/D не пересекаются: `[0; 1)`, `[1; 1,2)`, `[1,2; 1,4)`, `[1,4; 1,6)`, `[1,6; +∞)`. Группировка использует значения до округления. Верхняя граница исключена, нижняя включена.
- Широкая таблица прокручивается внутри своего контейнера. Мобильное меню закрывается по Escape с возвратом фокуса, по ссылке или клику вне шапки.

## Проверки

Проверено встроенным тестовым модулем Node.js 24, без установки пакетов:

```text
node --test tests/metrics.test.mjs tests/statistics.test.mjs tests/site.test.mjs
```

18 тестов проверяют согласованность данных, формулу, арифметические средние, пять топов, границы K/D, суммы распределений, ссылки, метаданные, активную навигацию, подписи полей, ARIA-связи и отсутствие надписей разработки. Пороги раскрытия и сохранение состояния при сортировке также проверены изолированно на DOM-модели, включая случай семи команд, без изменения набора игроков.

В локальном встроенном Chromium-браузере фактически проверены:

- Переходы по основному меню всех шести страниц и ссылкам подвала; мобильное меню и Escape.
- Поиск, совместная работа обоих фильтров, пустые результаты, сброс и 12 направлений сортировки рейтинга.
- Выбор профиля мышью и клавиатурой, автоподсказки, прокрутка списка, сброс старого выбора, корректный и неверный id.
- Переход из профиля в сравнение, заполнение именно левого поля, повторный выбор одного игрока, равенства, обмен местами и сброс.
- Все пять топов статистики, ссылки на профили, сортировка команд, раскрытие стран 8 → 18 → 8 и сохранность данных. У текущих шести команд кнопка раскрытия скрыта.
- Совпадение показателей выбранных игроков между главной, рейтингом, профилем, сравнением и статистикой.
- 40 сочетаний восьми состояний страниц с ширинами **1440, 1024, 768, 375 и 320 px**: переполнение страницы, ширина проверяемых заголовков и значений, пересечение элементов шапки. У таблицы отдельно проверена горизонтальная прокрутка клавиатурой внутри контейнера.
- Контраст основных текстовых сочетаний; номера карточек топ-3 приведены к контрасту 6,13:1 на белом фоне.

В пройденных браузерных сценариях ошибок JavaScript не зарегистрировано. Эти проверки не означают сертификацию доступности.

Остаётся вручную проверить перед или после публикации:

- Другие браузеры, особенно Firefox и Safari, и реальные сенсорные устройства с экранной клавиатурой.
- Озвучивание интерфейса экранным диктором, увеличенный системный шрифт и масштаб 200%.
- Полную проверку HTML профильным валидатором и полный аудит доступности.

## Публикация на GitHub Pages

Опубликуйте корень проекта из ветки с файлами сайта, выбрав папку `/(root)` в настройках GitHub Pages. Начальный файл — `index.html`. Сохраните структуру `css/`, `js/` и относительные пути: они подходят для адреса вида `username.github.io/FragRank/`. Сборка и сервер приложения не нужны.

После публикации откройте все шесть страниц и прямую ссылку на профиль с `id`. Автоматическая публикация и Git-коммиты инструментами проекта не выполняются.
